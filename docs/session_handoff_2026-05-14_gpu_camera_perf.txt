8. Interpretation for camera purchase / Path B
-----------------------------------------------
What was disproven:
  The computer is not too weak for current 4-camera FullHD streaming.
  CPU is not the raw camera bottleneck.
  GPU is now working and can run TensorRT pose/ball fast enough for 30 FPS compute when UI load is reduced.

What remains true:
  Current cameras are USB2, rolling-shutter, software-synced UVC cameras.
  They can stream 30 FPS, but not with precise hardware sync.
  Latest-frame timestamp spread is around 20-40 ms.
  For slow assessment/MVP this can be acceptable.
  For fast jumps, cuts, ball motion, and serious validation, this is still a camera-layer limitation.

Path B value:
  Path B should not be sold as "the computer cannot handle current cameras".
  Path B should be sold as:
    hardware synchronization
    global shutter
    less motion blur
    higher reliable capture rate
    better Z-axis/fast-motion credibility
    better validation-study credibility

Path B risk:
  4x120 FPS is realistic with proper USB3/PCIe architecture and NVMe.
  4x200 FPS should not be promised as the main production mode.
  For 4 high-speed USB3 cameras, buy/plan proper independent USB channels.
  A normal 4-port USB hub is not enough if it shares one upstream bottleneck.

Recommended hardware before Path B:
  1 TB NVMe SSD
  PCIe USB3 card with independent channels, or a verified controller distribution plan
  Better lighting
  Laser distance meter for tag/camera coordinate measurement

Recommended cheaper hardware experiment:
  Test 2 cheaper 2MP/FullHD 120 FPS global-shutter USB3 cameras before buying 4 FLIR cameras.
  Validate:
    Linux support
    manual exposure/gain lock
    hardware trigger support
    real 120 FPS at target resolution
    timestamps
    SDK/OpenCV integration
    lens/FOV suitability


9. Camera height / Z-axis discussion
------------------------------------
Current camera positions in arena_fixed/cal/extrinsics/Dimensions_fixed.txt:
  CamNorth = (5, 110, 226) cm
  CamEast  = (162, 5, 212) cm
  CamWest  = (160, 297, 217) cm
  CamSouth = (618, 153, 227) cm

All cameras are roughly in one high band: 212-227 cm.

Known systematic bias from arena_fixed calibration:
  Ball static bias around X+60, Z-104 mm
  Joint-touch bias around X+83, Z-125 mm

Interpretation:
  Trying one camera at a clearly different height, such as mid-wall height, is a reasonable A/B experiment.
  It may improve vertical geometry and Z-axis observability for knees, hips, and low ball positions.
  But moving cameras requires full extrinsics recalibration.
  Changing camera/lens/resolution requires intrinsics recalibration or verified K scaling.

Recommendation:
  Do not disrupt the current working calibration casually before important tests.
  Treat camera-height changes as a separate A/B calibration experiment.

# Footbonaut 3D Calibration, Reconstruction, & Inference Documentation

## 1. Pipeline Architecture (End-to-End)
This pipeline is a dual-camera, synchronized 3D ball detection and tracking system designed for high-precision metric analysis in a Footbonaut environment.

**Core Tech**:
* **Detector**: ultralytics YOLOv12/YOLOv26 (End-to-End)
* **Optimization**: NVIDIA TensorRT (FP16 Precision) + Parallel Threaded I/O
* **Tracker**: Hungarian Matching (ID Stability)
* **Reconstruction**: Linear Triangulation (`reconstruction.py`)
* **Visualization**: Isometric 3D Field Projection (1080p Grid)

### Pipeline Stages:
1. **Dual Frame Acquisition**: Frames are read simultaneously from Cam A (Main) and Cam B (Side). VideoLoader threads ensure non-blocking I/O, synced perfectly by index.
2. **TensorRT Inference**: Runs sequentially on both frames for maximum compatibility with TensorRT fixed batch sizes.
3. **2D Tracking (Stability)**: Independent trackers maintain temporal continuity in each cam view.
4. **3D Triangulation**: Metric (X, Y, Z) coordinates are calculated. Uses projection matrices from `calibration.npz`. Coordinates are in meters relative to the Cam A origin.
5. **Field Box Visualization**: Data presented in a 1920x1080 grid. Bottom-left panel shows the ball inside a virtual cage. Trajectory trails and floor "shadows" provide depth perception.

## 2. Intrinsic Calibration Techniques
- **Board Type**: Custom ChArUco (7x10 squares)
- **Square Size**: 40mm (0.040m)
- **Marker Size**: 30mm (0.030m)
- **Crucial Fix**: The physical board used a non-standard marker ID layout. Standard OpenCV Charuco detection failed to map IDs correctly to 3D object points.
- **Implementation Approach**: 
  * Manually constructed the `cv2.aruco.Board` with explicit 3D object points.
  * Used `cv2.aruco.ArucoDetector` for robust marker detection.
  * Implemented a custom point-matching fallback between detected markers and the manually defined board grid.
- **Result**: Reduced reprojection error from ~96px to ~1.5px.

---

## 3. Extrinsic Calibration & Spatial Alignment
- **Physical Setup**: Two cameras mounted on perpendicular walls, each approximately 5m from the shared corner.
- **Theoretical Baseline**: ~7.07m ($\sqrt{5^2 + 5^2}$).
- **Calibration Board**: 6x4 squares (210mm square length).
- **Scale Synchronization**: 
  * Initially, the calibrated baseline was ~12.25m using the raw 0.210m square size.
  * Calculated a scale factor to sync the virtual baseline with the physical 7.07m.
  * Adjusted the `square_len` parameter computationally in `start_calibration.py` to `0.1212m`.
- **Final Result**: Calibrated baseline is now ~7.08m, providing 1:1 scale metric accuracy for 3D tracking.
- **Dynamic Anchoring/Alignment**: Affine corrections are performed dynamically shifting the origin point via SVD/Kabsch optimizations to accurately land reconstructed vectors cleanly on the Y=0 ground plane.

---

## 4. 3D Reconstruction (Triangulation) Details
- **Method**: Linear triangulation using projection matrices derived from intrinsic and extrinsic parameters.
- **Pipeline Execution**: 
  * 2D centroids (x, y) are extracted from Camera A and Camera B.
  * Centroids are undistorted using intrinsic camera matrices and distortion coefficients.
  * `StereoTriangulator` computes the 3D (X, Y, Z) intersection point in the world coordinate system (anchored strictly to Camera A).

---

## 5. Field Visualization Details
- **Coordinate System**: Ground plane securely resides at physical Y=0 (relative to camera height).
- **Field Box**: Defined explicitly as a 14m x 14m area with a 4m height.
- **Output Matrix**: Rendered natively as a 1920x1080 2x2 grid featuring Cam A View, Cam B View, Isometric 3D Field View, and a real-time Telemetry Panel.

## 6. Quickstart / Operational Guide

### Essential Files:
- `start_calibration.py`: Performs the automated calibration workflow process and saves calibration.npz.
- `reconstruction.py`: Contains the core `StereoTriangulator` and the custom ChArUco board layout logics.
- `dual_inf.py` / `stereo_inference.py`: The main 3D inference and visualization framework engine driving the UI.
- `calibration.npz`: Stores the final intrinsic/extrinsic parameters output.

### Using the System:
**1. Running Calibration (Required when moving cameras)**
1. Capture identical videos of the intrinsic board (7x10) and extrinsic board (6x4).
2. Save them strictly into `pitch/calibrationA.mp4` & `pitch/calibrationB.mp4`.
3. Run the target script:
   ```bash
   python3 start_calibration.py
   ```
4. Verify the console out stream guarantees a reprojection error target `< 2.0px`.

**2. Running 3D Inference**
```bash
python3 dual_inf.py --camA pitch/camA.mp4 --camB pitch/camB.mp4 --model model/y26s_v1.engine
```
Key configurable flags:
- `--model`: Path to your quantised TensorRT engine.
- `--out`: Destination for the 2x2 grid video output.

*To adjust tuning heuristics mid-flight, modify `config/config.yaml` to adjust `conf` (normally 0.4 - 0.7) and `jitter_thresh` (ignoring micro-movement pixels).*
